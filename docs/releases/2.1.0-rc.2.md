# CHttp 2.1.0-rc.2

This prerelease migrates the internal cjwt JWS/JWE backend to `Salts::Crypto`,
using GmSSL/libecc providers. It retains the App layout introduced in rc.1.
Chttp's public JWT Bearer admission remains HS256-only.

## Changes

- Replace the internal HS256-only backend and unsupported JWE adapter with
  Salts-owned immutable keys and complete cjwt JOSE operations. Restore the
  existing asymmetric/JWE regression tests and add independent interoperability
  vectors. No OpenSSL or BoringSSL runtime dependency is introduced.
- Support HS/RS/PS 256/384/512, ES256/384/512/256K, Ed25519/Ed448, RSA-OAEP,
  RSA-OAEP-256, direct keys, AES-KW, PBES2 and AES-GCM 128/192/256 internally.
- Use the complete PBES2 salt during encryption, matching decryption. Invalid
  iteration counts, short content keys and inconsistent key components fail.
- Restore GmSSL through the manifest for the static Salts Crypto dependency.

## Dependencies and compatibility

Requires SaltsUtils Native 4.3.0-rc.4 and GmSSL 3.2.0 port revision 9 from the
shared vcpkg-cache registry. The Salts SDK remains in the 2.3.0 RC family.
Restore matching RID/profile SDKs and rebuild consumers. Provider types remain
private; there is no OpenSSL compatibility alias or runtime provider fallback.
Rollback requires the matching older CHttp and SaltsUtils packages together.

## Qualification and limits

The migration passed the 11 cjwt CTest targets in Windows Release and
Debug/ASan before being ported to the rc.1 App baseline. The matching Crypto
suite passed all 8 targets in both configurations. Tests include independent
JWS/JWE vectors, PEM/JWK imports, PSS salt boundaries, RSA component keys,
long PBES2 salts, tamper rejection and provider RNG failures.

After porting to the rc.1 App baseline, the complete Windows MSVC SDK Release
graph passed 102/102 CTests with the matching locally built Crypto SDK.
The formal installed App consumer test also passed 1/1.

The release workflow qualifies this source revision through full Linux,
macOS and Windows builds/CTests and Android/iOS build-only SDK jobs before
publishing the five-RID NuGet package. SDK manifests record producer SHAs.
Mobile device execution is not covered.

**HIGH: independent cryptographic security qualification remains open.**
Functional vectors and ASan do not establish resistance to side channels.
New provider RSA arithmetic/encodings and key parsing require independent
review, including generated code on each supported platform. This is an RC,
not a claim of completed cryptographic audit.
