# CHttp 2.1.0-rc.1

This prerelease adds configurable CNet composition and refactors the HTTP
server into explicit configuration, interception and transport ownership
boundaries. It targets the Salts 2.3 / SaltsUtils 4.3 SDK family.

## Changes

- Fully merge Service and Web into `app/`, one `CHttp::App` shared-library target
  and `<chttp_app/app.h>`. Existing capability function names, layouts and
  resource owners are preserved. The IDL/Jinja example uses the merged module.
- Add client destination-policy and server owner-placement configuration
  without changing existing public struct layouts. HTTP policy and protocol
  state remain owned by Chttp.
- Use one unified CNet Manager per server owner for adoption and terminal
  retirement, with bounded Handoff admission. Retired attachments retain
  WebSocket and H1/H2 deferred context until their terminal obligations finish.
- Track server retirement candidates in bounded intrusive lists, avoiding
  empty-list scans of all connection slots. No CPU percentage improvement has
  been measured.
- Manage dedicated H1/H2 WebSocket client and H2 pool transport lifetimes
  through CNet Manager. Stop failures preserve live protocol storage.
- Split the HTTP server example into Configurator, Interceptor and business
  handlers, using generated IDL MethodPlan/native bindings and Jinja templates.
- Retain the Service boundary: exact native capability admission at mount,
  independent per-invocation storage, bounded executor admission and retained
  Plugin lease for deferred DSO services.

## SDK and crypto boundary

The native workflow resolves floating `Salts.Native 2.3.0-*` and
`SaltsUtils.Native 4.3.0-*`; it does not fall back to older ABI families.
Both packages are restored explicitly alongside `CHttp.Native`.
Set `SALTS_ROOT`, `SALTS_UTILS_ROOT` and `CHTTP_ROOT` to the same RID and profile.
Rebuild consumers; do not retain the old separate CNet Manager DLL.
Service/Web consumers also need to replace their link targets with
`CHttp::App` and includes with `<chttp_app/app.h>` (or its service/web capability
headers). Deploy `chttp_app` instead of the two old libraries. This is a binary
deployment change requiring relinking; use a clean installation prefix.

Chttp does not directly link OpenSSL or BoringSSL. HTTPS/H2/WSS TLS uses
Salts CNet's private GmSSL backend, while JWT HS256 and protocol digests use
Salts Core's GmSSL-backed APIs. SaltsUtils Crypto also uses private libecc
code. GmSSL is not exposed as a consumer CMake dependency. Provider migration
does not broaden Chttp's JWT algorithm contract or enable new TLS variants.

The separate Salts ManagedDial close-retry patch remains an upstream change;
it is not included in `CHttp.Native` or in the unmodified published rc.3 SDK.
Chttp's Manager integration does not depend on ManagedDial recovery.

## Qualification and limits

The preceding refactor passed Windows Clang Release 99/99, MSVC SDK Release
95/95 and coherent Debug/ASan 99/99 CTest tests. Those results are recorded in
[the server verification table](../../http_server/README.md).
The local rc.1 MSVC SDK Release build against restored Salts `2.3.0-rc.3`
(commit `21a88ca4d80a76341fb8164cd33ceed3a3eb3d57`) and SaltsUtils `4.3.0-rc.2`
(commit `c96a47b05292e3bbebba0b016c0b18c71bce8cde`) passed 95/95 CTest tests
after the complete App shared-library merge.
This includes the unified App C++ header and IDL/Jinja HTTP example tests.
The independent installed App behavior test also passed 1/1, exercising
Web adapters, the Service runtime and Jinja HTML autoescape through the
installed `CHttp::App` shared library.
Local results do not prove Linux/macOS or mobile device execution.

Web renderers are synchronous and non-reentrant. Parallel workers need their
own renderer or external serialization. Service mounts and borrowed providers
remain immutable until all servers and accepted tasks have stopped. Automatic
reconnect, online component replacement and a new SG host/thread model are
outside this prerelease.

Review found that reinitializing an already live Web renderer overwrites its
handle instead of rejecting the call; destroy it before calling init again.
The dedicated RpcService installed example only compiles header initializers.
It does not qualify runtime linkage. The installed App behavior test covers
the merged Service and rendering runtimes through `CHttp::App`, while
MethodPlan/Plugin/deferred behavior relies on the formal integration suite.

The locally prepared Windows-only artifacts are not the five-RID release
package. Publication uses the matching version-tag workflow: Linux, macOS
and Windows build/test/install plus Android/iOS build-only must succeed before
packing and publishing. Each SDK contains the exact source SHA and selected
Salts/SaltsUtils producer manifests. Manual dispatch prepares artifacts without
publishing. The tag workflow publishes the NuGet package and creates a GitHub
prerelease; published versions must not be reused for different content.
