# CHttp 2.1.0-rc.5

This is a **prerelease of the CHttp 2.1 line** based on the already CI-qualified
RPC Owner integration, released before external/downstream application
qualification at the maintainer's explicit direction.

## RPC Server and Client converge on CNet Owner

- Bind RPC registry/configuration and generated DataBind service mounts directly
  to the existing HTTP Server Owner using `chttp_server_rpc_*`.
- Make synchronous and asynchronous RPC requests through existing
  `chttp_client_rpc_*` / `chttp_async_client_rpc_*` APIs, retaining bounded
  call slots, deadline/cancel and exactly-once completion semantics.
- Remove the standalone installed `CHttp::RpcService` target and its independent
  Server/Client transport owners. **No legacy fallback or compatibility alias**.
- Verify bounded native DataBind frames, exact rollback on partial failure,
  duplicate wire ID rejection, retained Provider DSO Generation leases,
  cancellation/drain barriers and owned CMeta-string final release.
- Retain the deterministic Windows IOCP Acceptor rejection test: observe a real
  bounded admission reject, then prove an existing HTTP connection continues
  processing; do not infer server admission from a completed client connect.

## Exact published upstream SDKs

- Salts.Native **2.3.0-rc.15**, immutable upstream source
  `21bdb1145fbb2b39ee3fa644173ec037adba7b87`.
- SaltsUtils.Native **4.3.0-rc.10**, immutable upstream source
  `1410c9fd479f9faab31503523d8e31cc506b5b25`.
- Normal Linux/Windows SDK restore uses NuGet exact-version selectors
  `[2.3.0-rc.15]` and `[4.3.0-rc.10]`, with resolved version verification.
  Rebuild all consuming applications against the matching native ABI.
- Salts/CNet's POSIX `cmeta_once_t` is now backed by native `pthread_once_t`.
  Mixed release DSO / TSan CHttp tests validate the new once-publication ABI,
  not the previously published pre-fix Salts rc.14.

## Release CI and qualification

The source baseline is CHttp Draft PR #245 commit
`ebd4d90216b15bc9d05c9dec5f3171827ee72827`; this release branch changes only the
version manifest, these notes and the gated CI release entrypoint. The full
source baseline passed six CHttp workflows on the exact SHA, including ordinary
ASan/UBSan + TSan, full-source TSan, candidate NuGet six-RID conformance,
and official released upstream pair six-RID installed-consumer conformance.

The release CI must independently build/test the **five packaged targets**:
Linux x64, Windows x64, macOS arm64, Android arm64-v8a and iOS arm64,
including Windows native CTest and installed App/RPC consumer checks before
the package can be published.

## Downstream post-release qualification — OPEN

The release deliberately **does not** claim all downstream applications have
been tested. TurboAgent and other actual CHttp consuming projects must compile
and execute their installed-SDK C11/C++ tests with this exact prerelease, audit
removed standalone `CHttp::RpcService` dependencies and validate real RPC,
cancellation, and DSO lifecycle semantics. Failures are tracked after the
prerelease; stable promotion and broader migration are separate decisions.

This RC does not assert TLS/GmSSL provider security certification, complete
downstream conformance, or compatibility with the removed RPC-owner APIs.
